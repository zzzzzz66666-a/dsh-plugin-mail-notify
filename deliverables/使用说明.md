# DeepSeek Harness 邮件通知与邮件续聊插件 · 使用说明

版本 1.0.0 · 适用平台：Windows + DeepSeek Harness 桌面版 · 首版通道：QQ 邮箱

---

## 1. 这个插件做什么

你让 DeepSeek Harness 跑任务时不用一直盯着窗口。**每一轮任务结束时，它会给你发一封摘要邮件**；你**直接回复那封邮件**，就能把内容送回原来的对话，让它接着干。

具体能力：

- 轮次以**完成**、或**失败/被拦截/达到输出上限**结束时发信。你按了停止、或被打断的轮次不发信——那通常只是你在它干活时又发了一条消息。
- 邮件包含：状态、任务标题、本地任务编号、会话摘要、开始与结束时间、耗时、**本轮回复摘要**、错误摘要、回复验证码、回复说明。
- 回复摘要默认保留 600 字，超出会标注截断；也可关掉。
- 邮件**只发摘要**，不含完整模型输出、工具日志、命令输出，也不含你的邮箱授权码。
- 断网时通知先落本地队列，恢复后自动补发；最多自动重试 5 次，可手动重发。
- 回复要经四重校验（白名单发件人 / 任务编号 / 回复验证码 / 24 小时有效期）外加 Message-ID 去重、附件与长度限制，才会提交。
- **权限审批永远不会通过邮件批准**，必须回到 Harness 窗口里操作。
- 手机随时能收。你人在外面、在开会、在干别的，任务完了邮件就到；想继续就回一句话。

## 2. 安装前需要准备

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10 / 11 |
| Harness | DeepSeek **桌面版**已安装并使用过（存在 `%USERPROFILE%\.dsh\profiles\desktop`） |
| 邮箱 | 一个 QQ 邮箱（或腾讯企业邮箱） |
| 授权码 | QQ 邮箱 → 设置 → 账户 → 开启「IMAP/SMTP 服务」后生成的 16 位授权码 |

**授权码不是 QQ 密码。** 它只用于让插件登录你的邮箱收发信，可以随时在 QQ 邮箱里作废重发。

## 3. 安装

有两种方式，**推荐第一种**。

### 3.1 让你的 AI 助手装（推荐）

发布目录里带了一份**安装技能** `skill\dsh-mail-notify-install`。把它装到 Harness 的技能目录：

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.dsh\skills" | Out-Null
Copy-Item -Recurse '<发布目录>\skill\dsh-mail-notify-install' "$env:USERPROFILE\.dsh\skills\"
```

重启 Harness 会话后，直接对助手说「帮我装 DeepSeek Harness 邮件通知插件」即可。它会自己完成：写配置、装依赖、结构校验，并把需要你自己做的那一步（输入授权码）交给你。

技能里有几条硬性约束值得知道：

- **授权码不会出现在命令行和对话里**：它要求你把授权码写进临时文件，再用管道喂给脚本，用完提醒你删除。
- 它不会擅自重启你的 Harness，也不会绕过沙箱与审批。
- 没有跑验证就不会告诉你"装好了"。

### 3.2 自己装（三分钟）

1. 把 `dsh-plugin-mail-notify-1.0.0.zip` 解压到一个**固定目录**，例如 `D:\dsh-plugin-mail-notify`。
   目录里应能看到 `package.json`、`lib`、`scripts`。
2. 打开 PowerShell：

```powershell
$node = "$env:USERPROFILE\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe"
cd D:\dsh-plugin-mail-notify

# ① 写配置（不碰授权码）
& $node .\scripts\configure.mjs --sender 你的邮箱@qq.com --no-credential

# ② 存授权码：会提示你输入，过程中不回显
& $node .\scripts\set-credential.mjs

# ③ 结构校验，应该看到 14/14 passed
& $node .\scripts\verify-install.mjs
```

3. **完全退出 DeepSeek Harness 再重新打开**（关窗口不算，要确认进程真的退出了）。

安装脚本做三件事：给 profile 加一条插件依赖和一个插件行、创建数据目录 `%USERPROFILE%\.dsh\mail-notify`、把授权码写进 Harness 的凭据服务。
它**不改动你的任何项目文件**，且每次改动前都会把原文件备份到 profile 目录下的 `.mail-notify-backup-<时间戳>\`。

## 4. 配置邮箱

上面的 `--sender` 就是发件邮箱。收件与允许回复的地址默认与它相同（单邮箱自收自发，最常见）。

想分开，用这些参数：

| 参数 | 作用 |
| --- | --- |
| `--recipient 邮箱` | 换一个地址接收通知 |
| `--reply-to 邮箱` | 只允许这个地址回复（默认与收件相同） |
| `--prefix "[标签]"` | 邮件主题标签，默认 `[DSH]`；**也是收信搜索用的标记，改完之后旧邮件就搜不到了** |
| `--imap-mailbox INBOX` | 收件箱文件夹名 |
| `--data-dir <路径>` | 插件数据目录 |

服务器已内置 QQ 邮箱正确值，无需填写：

| 设置项 | 值 |
| --- | --- |
| SMTP 主机 / 端口 / 加密 | `smtp.qq.com` / `465` / `ssl` |
| IMAP 主机 / 端口 / 加密 | `imap.qq.com` / `993` / `ssl` |

腾讯企业邮箱把主机换成 `smtp.exmail.qq.com` 与 `imap.exmail.qq.com`，用 `--smtp-host` / `--imap-host` 覆盖。
想先看不写盘，加 `--dry-run`。

**授权码只写进 Harness 凭据服务**（`%USERPROFILE%\.dsh\.credentials.yaml` 的 `refs:` 分节，引用名 `DSH_MAIL_NOTIFY_AUTH_CODE`），普通配置文件里没有它。

## 5. 日常使用

配置完成后不需要任何额外操作。插件随 Harness 运行，每 15 秒检查一次邮箱、任务结束时自动发信。

收到的摘要邮件长这样：

```text
主题：[DSH][completed] 任务标题 - task-d9043a-t17

状态：completed
任务标题：任务标题
本地任务编号：task-d9043a-t17
会话标识摘要：session-1
开始时间：2026-10-17T01:01:51.699Z
结束时间：2026-10-17T01:04:52.467Z
耗时：180768 ms

本次回复摘要：
已经把这个插件的邮件通知补全了：完成时发摘要，正文里带上我这次的答复……

错误摘要或等待原因：无

回复验证码：8E5A40E6
回复有效期：24 小时内可多次回复
回复说明：直接回复本邮件并在正文保留上面的任务编号与验证码，即可向原会话提交内容。
权限审批不能通过邮件批准，请回到 DeepSeek Harness 内处理。
```

### 用邮件继续对话

**直接回复那封邮件**，正文里保留「本地任务编号」和「回复验证码」两行，下面写你要说的话：

```text
本地任务编号：task-d9043a-t17
回复验证码：8E5A40E6
把登录界面改成暗色主题
```

规则说明：

- **只接受"允许回复邮箱"发来的邮件**，其他地址一律拒绝。
- **验证码 24 小时内可重复使用**：同一封通知邮件可以连着回复多次（比如想到第二句再说一句）。过期后失效。
- **同一封邮件（Message-ID 相同）只处理一次**：重复投递不会重复执行。
- **引用原文、签名会自动剥离**：你不用手工删掉下面那一大段原始邮件，插件只把你写的内容送进对话。
- 附件会被拒绝；剥离引用后的正文上限 8000 字符。
- 原会话**正在运行**时，回复会排队，等当前轮结束后立刻开始新一轮——不会打断它。
- **权限审批不能通过邮件批准**。收到「等待审批」的提醒，请回到 Harness 窗口处理。

### 回复多久会生效

正常 **10–20 秒**：邮件投递 1–5 秒 + 最多等一轮轮询（默认 15 秒）+ 取信约 0.6 秒。

如果助手当时正在干活，你的回复会排队到这一轮结束——这是排队，不是延迟。

## 6. 常用命令

全部在插件目录下执行。`$node` 指 Harness 自带运行时：

```powershell
$node = "$env:USERPROFILE\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe"
```

| 命令 | 作用 |
| --- | --- |
| `& $node .\scripts\verify-install.mjs` | 检查安装结构（应 14/14 通过） |
| `& $node .\scripts\set-credential.mjs --check-only` | 复测已存的授权码是否仍能登录 |
| `& $node .\scripts\check-mailbox.mjs` | **排查"回复了没反应"**：只读，告诉你会不会被接受 |
| `& $node .\scripts\configure.mjs --sender <新地址> --no-credential` | 改邮箱地址 / 标签 |
| `& $node .\scripts\set-credential.mjs` | 换授权码 |
| `& $node .\scripts\uninstall.mjs` | 停用插件（保留依赖、凭据和数据） |
| `& $node .\scripts\run-tests.mjs` | 跑插件自带的 187 项自测 |

数据都在 `%USERPROFILE%\.dsh\mail-notify`：

| 文件 | 内容 |
| --- | --- |
| `audit.json` | 事件记录（已脱敏，不含授权码与验证码） |
| `notifications.json` | 通知队列与失败原因 |
| `state.json` | 任务映射、已处理邮件、IMAP 进度 |
| `tokens.json` | 回复验证码及有效期 |

想清空审计看个干净的开始（不影响功能）：

```powershell
Remove-Item "$env:USERPROFILE\.dsh\mail-notify\audit.json"
```

## 7. 出问题怎么办

| 现象 | 处理 |
| --- | --- |
| 收不到通知邮件 | 看 `notifications.json` 里那条的 `status` 与 `lastError`。`failed` 且写着 `authentication` 说明授权码失效，重跑 `set-credential.mjs` |
| 提示授权码被拒 | 回 QQ 邮箱确认「IMAP/SMTP 服务」是开启的，重新生成授权码再存一次 |
| 插件好像根本没加载 | 跑 `verify-install.mjs` 看是否 14/14；再确认确实**完全重启**过 Harness |
| 回复了但没进对话 | **先跑 `check-mailbox.mjs`**，它会分清是「没搜到」还是「搜到了但校验没过」，并给出具体原因 |
| 回复进了对话但很慢 | 看是不是助手当时正在干活（`submitted_running` 是排队）。若长期很慢，见下一条 |
| 通知一直发不出 | 大概率网络或邮箱限流；插件会指数退避重试 5 次，之后可在 `notifications.json` 里看到原因 |
| 改了标签后旧邮件没反应 | 标签同时是收信搜索标记，改之前发出去的邮件搜不到了 |

更细的排查见 `skill\dsh-mail-notify-install\references\troubleshooting.md`（每个现象都对应到具体命令和要看的文件）。

## 8. 卸载

```powershell
$node = "$env:USERPROFILE\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe"
cd D:\dsh-plugin-mail-notify

# 只停用：移除插件行，保留依赖、凭据与数据
& $node .\scripts\uninstall.mjs

# 连凭据一起移除
& $node .\scripts\uninstall.mjs --remove-credential

# 彻底清理：连依赖与插件数据一起删
& $node .\scripts\uninstall.mjs --remove-credential --remove-dependency --purge-data
```

卸载同样会在改动前备份。之后**完全重启** Harness 生效。
两种方式都不会删除你的项目文件或聊天记录。

## 9. 安全边界与已知限制

安全设计：

- 邮件正文**永远不会被当作系统命令执行**——它只是作为一条普通用户消息投进会话。
- 邮件**不能批准权限**，Harness 的沙箱与审批策略保持原样。
- 只接受白名单邮箱；验证码有 24 小时有效期；同一 Message-ID 只处理一次。
- 授权码只在 Harness 凭据服务里，不进配置文件、不进日志、不进审计。
- 发信只发摘要，不发完整输出。

已知限制：

1. 插件随 Harness 进程运行，**Harness 完全退出后不会提醒**。
2. **不能替你回答结构化的选择题**：Harness 要求按问题 id 提交结构化答案，自由文本无法可靠映射，所以这类回复会作为普通下一条消息提交，而不是选项答案。邮件里会写清楚。
3. 只在 **Windows** 上验证过。代码只用 Node 内置模块，理论上跨平台，但 macOS / Linux 未实测。
4. 首版只支持一个收件邮箱、一个允许回复邮箱，以及 SMTP/IMAP（`ssl` / `starttls`）。
5. QQ 邮箱的 IMAP 会**忽略主题文本搜索条件**，所以插件按日期窗口取信并在本地再筛主题；这带来每轮一次轻量取信开销，不影响正确性。
6. 短信通知未实现。
